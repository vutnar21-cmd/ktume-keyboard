## Задача

Убрать автоматическую заглавную букву при переключении курсора на строку, в которой уже что-то написано.

Как сейчас: при переходе на строку автоматически включается Shift (заглавная). Если строка пустая — это нормально, так и должно остаться. Если в строке уже есть текст, автоматическая заглавная очень мешает: приходится вручную переключать регистр, чтобы продолжить писать.

Нужно: автозаглавная срабатывает только на действительно пустой строке, куда пользователь собирается начать писать. При попадании курсора в строку с уже набранным текстом регистр должен оставаться нейтральным.

## Критерии готовности

- [ ] Курсор в пустой строке (новой или существующей, но без текста) — заглавная включается автоматически
- [ ] Курсор перемещён в строку, где уже есть текст (в начало, в середину, в конец) — заглавная не включается
- [ ] Однострочные поля и поля без переносов работают как раньше: заглавная только на пустом поле
- [ ] Настройка «Автозаглавная» по-прежнему полностью отключает это поведение
- [ ] `./gradlew assembleDebug testDebugUnitTest lintDebug --no-daemon` проходит без ошибок и предупреждений компилятора

## Ограничения

- Не ломать инварианты из `AGENT.md`: сборка только с JDK 21, `kotlin.incremental=false` не трогать, при смене дефолта настройки поднимать суффикс `preferencesKey`.
- Не менять поведение CAPS_LOCK и ручного двойного тапа по Shift — речь только об автозаглавной.
- Не переписывать целиком логику ввода/удаления в `KeskeImeService`: правка должна быть локальной.

## Отчёты

### 2026-10-23 · диагностика (к работе не приступал)

Причина видна в двух местах:

- `app/src/main/java/org/chuvash/keske/ime/KeskeImeService.kt:70` —
  `PreferencesState.isFieldEmpty.value = before.isEmpty() || before.endsWith("\n")`,
  где `before` — весь текст до курсора. Условие `endsWith("\n")` истинно и для начала строки,
  в которой уже есть текст, поэтому Shift включается при любом попадании курсора в начало
  непустой строки.
- `app/src/main/java/org/chuvash/keske/ime/KeyboardScreen.kt:102-116` — `shiftState`
  инициализируется и переключается в `ONCE` строго по флагу `isFieldEmpty`; проверки
  «в текущей строке уже есть текст» нет.
- Дублирующий расчёт того же флага в превью настроек: `SettingsActivity.kt:603`.

Направление правки: флаг должен означать «текущая строка пуста», а не «текст до курсора
кончается переводом строки». Достаточно проверить обе половины строки — текст до курсора и
текст после курсора до ближайшего `\n` (`getTextAfterCursor`). Поведение после Enter
(`before` кончается на `\n`, справа пусто) при этом сохранится. Конкретную реализацию
выбирает исполнитель; критерии — выше.

Проверка после правки — отдельный отчёт с результатом сборки и тестов.
