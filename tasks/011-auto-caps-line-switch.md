## Задача

Убрать автоматическую заглавную букву при переключении курсора на строку, в которой уже что-то написано.

Как сейчас: при переходе на строку автоматически включается Shift (заглавная). Если строка пустая — это нормально, так и должно остаться. Если в строке уже есть текст, автоматическая заглавная очень мешает: приходится вручную переключать регистр, чтобы продолжить писать.

Нужно: автозаглавная срабатывает только на действительно пустой строке, куда пользователь собирается начать писать. При попадании курсора в строку с уже набранным текстом регистр должен оставаться нейтральным.

## Критерии готовности

- [ ] Курсор в пустой строке (новой или существующей, но без текста) — заглавная включается автоматически
- [ ] Курсор перемещён в строку, где уже есть текст (в начало, в середину, в конец) — заглавная не включается
- [ ] Однострочные поля и поля без переносов работают как раньше: заглавная только на пустом поле
- [ ] Настройка «Автозаглавная» по-прежнему полностью отключает это поведение
- [ ] `./gradlew assembleDebug testDebugUnitTest lintDebug --no-daemon` проходит без ошибок и предупреждений компилятора

## Ограничения

- Не ломать инварианты из `AGENT.md`: сборка только с JDK 21, `kotlin.incremental=false` не трогать, при смене дефолта настройки поднимать суффикс `preferencesKey`.
- Не менять поведение CAPS_LOCK и ручного двойного тапа по Shift — речь только об автозаглавной.
- Не переписывать целиком логику ввода/удаления в `KeskeImeService`: правка должна быть локальной.

## Отчёты

### 2026-10-23 · диагностика (к работе не приступал)

Причина видна в двух местах:

- `app/src/main/java/org/chuvash/keske/ime/KeskeImeService.kt:70` —
  `PreferencesState.isFieldEmpty.value = before.isEmpty() || before.endsWith("\n")`,
  где `before` — весь текст до курсора. Условие `endsWith("\n")` истинно и для начала строки,
  в которой уже есть текст, поэтому Shift включается при любом попадании курсора в начало
  непустой строки.
- `app/src/main/java/org/chuvash/keske/ime/KeyboardScreen.kt:102-116` — `shiftState`
  инициализируется и переключается в `ONCE` строго по флагу `isFieldEmpty`; проверки
  «в текущей строке уже есть текст» нет.
- Дублирующий расчёт того же флага в превью настроек: `SettingsActivity.kt:603`.

Направление правки: флаг должен означать «текущая строка пуста», а не «текст до курсора
кончается переводом строки». Достаточно проверить обе половины строки — текст до курсора и
текст после курсора до ближайшего `\n` (`getTextAfterCursor`). Поведение после Enter
(`before` кончается на `\n`, справа пусто) при этом сохранится. Конкретную реализацию
выбирает исполнитель; критерии — выше.

Проверка после правки — отдельный отчёт с результатом сборки и тестов.

### 2026-10-23 · сделано, ждёт приёмки

Правка:

- `data/KeyboardLayouts.kt` — новый чистый хелпер `isCursorOnEmptyLine(beforeCursor, afterCursor)`:
  строка считается пустой, только если слева до `\n` и справа до ближайшего `\n` текста нет.
- `ime/KeskeImeService.kt` — `updateEditorContextState()` теперь берёт и `getTextAfterCursor(64)`
  (в `runCatching`, чтобы не падать на редакторах без поддержки) и считает флаг через хелпер.
- `ime/KeyboardScreen.kt` — добавлен `autoShiftArmed`: автозаглавная, включённая автоматически,
  снимается, когда курсор ушёл в строку с текстом. Ручной Shift, CAPS_LOCK, заглавная после
  `.`/`!`/`?` и после Enter не затрагиваются (в этих местах флаг сбрасывается).
- `ime/SettingsActivity.kt:603` — превью настроек считает флаг той же функцией, расхождения с сервисом нет.
- `KeyboardLayoutsTest.kt` — новый тест `isCursorOnEmptyLine_trueOnlyForReallyEmptyLine` на 8 кейсов,
  включая главный (курсор в начале непустой строки → `false`).

Проверка: `./gradlew assembleDebug testDebugUnitTest lintDebug --no-daemon` (JDK 21) —
**BUILD SUCCESSFUL**, тесты и lint прошли, предупреждений компилятора нет.

Что осталось проверить на устройстве:
1. Тап в начало строки, где уже есть текст → заглавной нет.
2. Тап в пустую строку между двумя заполненными → заглавная есть.
3. Enter в конце текста → заглавная есть.
4. Настройка «Автозаглавная» выключена → заглавной нет нигде.

APK собран и передан владельцу: `keske-011-autocaps-debug.apk`.

### 2026-11-01 · 95 % · статус `review` (поведение Gboard: поля ввода и точка)

**Доработка по замечаниям владельца с устройства:**

1. *«Большая буква при переключении на поле ввода не должна быть по умолчанию, как в Gboard»:*
   раньше `beforeSeq != null` в `KeskeImeService` форсировал автозаглавную в любом пустом поле,
   игнорируя `EditorInfo.inputType` (URL, поиск, email, пароли, терминал, обычные веб-поля).
2. *«Если после точки есть символ, не начинать с большой буквы (email, сайты, команды)»:*
   раньше нажатие клавиши `.` сразу включало `ShiftState.ONCE` без ожидания пробела (`site.Com`,
   `user.Name`, `./Gradlew`).

**Сделано:**

- `KeyboardLayouts.resolveEditorCapFlags(inputType)` — разрешает автозаглавную только в текстовых
  полях, которые сами запрашивают `TYPE_TEXT_FLAG_CAP_*`, и жёстко блокирует `TYPE_NULL`,
  `URI`, `EMAIL_ADDRESS`, `WEB_EMAIL_ADDRESS` и `*PASSWORD`.
- `KeyboardLayouts.shouldAutoCapitalize(beforeCursor, afterCursor, editorCapFlags)` — включает
  заглавную только при `editorCapFlags != 0`, отсутствии символов справа на текущей строке
  (`lineAfter.isEmpty()`) и только на пустой строке либо после конца предложения **с пробелом**
  (`"Салам. "`, `"Епле? "`, `"Тавтапуҫ! "`), не срабатывая на `ivan.petrov`, `chuvash.org`,
  `./gradlew`, `. ~/.bashrc`, `cd .. ` и при курсоре перед символом (`ivan.|petrov`).
- `PreferencesState`: `shouldAutoCapitalize` по умолчанию `false` + `inputSessionId` для сброса
  одноразового Shift прошлого поля в `onStartInputView(restarting = false)`.
- `KeyboardScreen`: убраны безусловные локальные включения `ShiftState.ONCE` на клавишах `.` и `Enter`;
  убран спам `Log.d("KeskeCaps")` из `KeskeImeService`.
- Добавлены unit-тесты `resolveEditorCapFlags_respectsGboardFieldRules` и
  `shouldAutoCapitalize_preventsCapsInEmailsUrlsCommandsAndMidLine`.
