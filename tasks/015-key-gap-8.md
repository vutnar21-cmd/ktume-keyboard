## Задача

Расстояние между клавишами по умолчанию — 8 (сейчас 3).

## Критерии готовности

- [ ] `keyGapDp` по умолчанию = 8
- [ ] Новое значение применяется на устройстве, где уже сохранены настройки
- [ ] Подпись ползунка в настройках говорит «по умолч. 8»

## Ограничения

- Ширина клавиши считается как `(ширина − gap × (колонок − 1)) / колонок`, поэтому при
  8 dp клавиши станут уже; проверить, что 10 клавиш в ряду не сжимаются ниже читаемого.
- Ключ хранилища версионирован: при смене дефолта суффикс нужно поднять (`_v5` → `_v6`).

## Отчёты

### 2026-10-23 · 100 % · статус `review`

**Сделано.** `keyGapDp` по умолчанию = **8** (было 3).

- `KeyboardPreferences`: `keyGapDp = 8f`.
- `PreferencesRepository`: ключ `key_gap_dp_v5` → `key_gap_dp_v6`, дефолт чтения `8f` —
  новое значение применится на устройстве, где уже сохранены настройки.
- Подпись ползунка: «по умолч. 8».

**Предупреждение (из консультации с Argon).** При 10 клавишах в ряду и ширине экрана 360 dp
клавиша сжимается с ~33 dp до ~29 dp: `(360 − 8×9) / 10`. На узких экранах текст может
начать обрезаться. Если это проявится — вернуть 5–6 dp или сделать gap адаптивным
(меньше на узких экранах).

**Проверено:** тест дефолтов обновлён (`8f`), сборка и 21 тест зелёные, lint 0.

### 2026-10-23 · консультация Argon + откат на 3 dp

**По просьбе владельца значение откатано к 3 dp** (сборка и тесты зелёные).
Ключ хранилища возвращён на `key_gap_dp_v5`, подпись ползунка — «по умолч. 3».

**Ответ Argon (`google/gemini-4-argon`, RouterAI) на вопрос «какой зазор оптимален»:**

| Ось | Рекомендация |
|---|---|
| Горизонталь (между клавишами в ряду) | **4–6 dp** (Gboard и iOS: ~5–6 dp) |
| Вертикаль (между рядами) | **6–8 dp** |
| Отступ от края экрана | 3 dp |
| Тач-зона | **0 dp gap** — хитбоксы вплотную, зазор только визуальный |

Почему 8 dp по горизонтали — ошибка: на экране 360 dp при 10 клавишах зазор съедает 88 dp
(24 % ширины), клавиша падает до 27.2 dp. При шрифте 26 sp внутренний паддинг — 2.5–4 dp,
буквы прилипают к краям, а со скруглением 14 dp клавиша превращается в узкую капсулу.

Ширина клавиши при 360 dp / 10 клавиш:

| gap | Ширина клавиши |
|---|---|
| 3 dp | 32.7 dp |
| 6 dp | 29.4 dp |
| 8 dp | **27.2 dp — критически узко** |

Адаптивный зазор — от ширины экрана, но **не** от числа колонок (в рядах на 9 и 7 клавиш
зазор должен быть тем же, иначе ломается визуальная сетка):

```kotlin
val screenWidth = LocalConfiguration.current.screenWidthDp.dp
val hGap = (screenWidth * 0.015f).coerceIn(4.dp, 7.dp)   // 360dp -> 5.4, 412dp -> 6.2
val vGap = (hGap * 1.3f).coerceIn(6.dp, 9.dp)            // 360dp -> 7.0
```

Что важнее: **высота клавиши**. Закон Фиттса — площадь мишени; вертикальный разброс пальца
на 30–40 % выше горизонтального; 48 dp — индустриальный и accessibility-минимум.

**Итоговая рекомендация Argon:** горизонталь 5 dp (или формула), вертикаль 7 dp,
edge padding 3 dp, визуал отделить от тач-зоны.

**Нужно от владельца:** оставить единый `keyGapDp = 3` или ввести раздельные `hGap`/`vGap`
(5 и 7 dp) по формуле. Сейчас в коде одно значение на обе оси.

### 2026-10-23 · раздельные зазоры + ползунки · статус `review`

По решению владельца: горизонталь 3 dp, вертикаль 7 dp, асимметрия допустима,
значения крутятся ползунками.

- `KeyboardPreferences`: `keyGapDp` разбит на `keyGapHDp = 3f` и `keyGapVDp = 7f`.
- `PreferencesRepository`: ключи `key_gap_h_dp_v6` / `key_gap_v_dp_v6`;
  старый `key_gap_dp_v5` читается как fallback — сохранённое значение не потеряется.
- `KeyboardScreen`: `hGap` для `Row.spacedBy`, `vGap` для `Spacer` между рядами;
  ширина клавиши считается по `hGap`.
- `NumpadGridView` принимает оба значения, `EmojiPickerPage` — только `hGap`.
- **Hex не тронут**: использует `keyGapHDp`, геометрия сот осталась прежней.
- Настройки: два ползунка — «Зазор по горизонтали» (0–10) и «Зазор по вертикали» (0–14).

**Проверено:** сборка, 21 тест, lint 0 ошибок. На устройстве не проверялось:
владелец покрутит ползунки и скажет, какие значения оставить.

**Важно:** хитбоксы пока **не** встык — попадание в зазор по-прежнему не делает ничего.
Это отдельная задача `018-tap-in-gap.md`.
